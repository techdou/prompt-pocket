# Prompt Pocket 升级实施计划

日期：2026-10-03。状态：本地实现已完成，验证结果与平台边界见 `verification.md`。

## 目标与范围

保持 Tauri + Svelte + Markdown 的现有产品路线。交付可靠的数据保护、全文检索与使用记录、变量模板、快速调用/整理两种界面状态、可配置快捷键和工程验证入口。保持中英文界面兼容。

现状依据：`src/App.svelte` 负责加载/编辑/复制/排序；`src/lib/search.ts` 仅搜索标题、分类和旧标签；`src-tauri/src/store.rs` 保存直接写盘、删除不可恢复；`src-tauri/src/sync.rs` 下载按大小比较且远程遍历失败后仍可能清理本地；`package.json` 没有统一测试/类型检查入口。

## 设计决定

- Markdown 继续作为可读的内容源；全文正文随扫描提供。收藏、使用次数和最近使用作为本地偏好，不改写每条提示词。
- 为保存/下载覆盖保留恢复副本；手动删除进入可恢复记录。恢复入口在设置内。失败时保留原文件。
- 手动上传/下载保留明确方向。远程清单不完整或下载失败时禁止清理；内容比较替代大小比较；本地独有文件默认保留；冲突保留副本并报告，不做静默双向合并。
- 模板语法 `{{字段}}` 与 `{{字段|默认值}}`，调用时填写，正文不回写。字段支持多行，最终预览显示原样输出。支持创建模板副本、插入已有提示词作为常用片段。
- 快速调用默认紧凑；整理模式保留双栏编辑。复用现有浅色/蓝色视觉、分类导航和键盘流程。
- 不进行大规模重写。只把可独立验证的加载状态、编辑状态、搜索/偏好/模板和同步状态抽出。

## 实施顺序与责任

1. 数据保护：`store.rs` + 新恢复模块。安全写入、保存失败保护、恢复删除/历史记录、安全分类移动。先加回归用例。
2. 同步：`sync.rs`。完整性门槛、内容校验、同步元数据统一、覆盖备份、冲突报告。与数据保护模块通过小接口集成。
3. 纯前端逻辑：`search.ts`、新模板/偏好/加载辅助模块及测试。正文权重、片段、高亮、最近/收藏、模板解析和渲染。
4. 入口与界面：根代理负责 `lib.rs`、API/类型、App/Editor/PromptList/Settings 集成；加载身份校验、未保存保护、分类保存、复制反馈、模板填写、恢复入口、紧凑/整理、自定义快捷键。
5. 工程：增加 `svelte-check`（用户已批准该建议）、统一 test/check/verify 命令、CI；README/设计文档更新。
6. 审查与验证：原生子代理独立审查，修复后运行完整前端和 Rust 测试、类型检查、构建、Clippy；浏览器预览覆盖主要界面并保存视觉检查结论。

## 清理计划与回归策略

先为文件写入失败、等长内容更新、模板多次变量、搜索正文和异步加载乱序建立回归用例；保留排序/语言现有测试。每次只提取一个边界，不新建通用状态框架，不改变既有 Markdown 兼容性。新增 `svelte-check` 开发检查工具，并升级 Vite 6 与匹配的 Svelte 插件，以修复构建依赖审计问题。

## 风险与控制

- Windows 粘贴无法在 macOS 宿主完整证明：以现有平台实现为基础，单测状态判断，明确实机验证边界。
- 用户真实 WebDAV 不作为测试目标：使用临时目录/本地模拟服务器验证内容与失败路径，不触碰真实提示词库。
- 并行修改：存储、同步、纯逻辑三个所有权互不交叉；根代理统一集成共享 API/UI。
- 路径与恢复安全：只接受库内相对路径，禁止恢复数据逃逸、隐藏目录作为分类和 symlink 绕过。
- 同步协议演进：旧元数据仅作为提示；缺乏共同基线时保守保留冲突副本，不据此删除文件。
